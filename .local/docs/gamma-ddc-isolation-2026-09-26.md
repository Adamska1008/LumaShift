# Gamma 与 DDC 故障隔离（0.1.2）

## 需求修正

0.1.1 对 DDC 通信做了重试，但沿用了“任何恢复失败则整体暂停”的设计。用户指出硬件能力不可用不应阻止 Gamma 基本功能；本次将故障及恢复记录按路径隔离。

## 行为

- 硬件读取、写入、校验或原值持久化失败：停用对应硬件控件，发出警告。Gamma 效果、预设和快捷键继续工作，其他可用硬件项仍可应用。
- 已暂停的硬件项不会随 Gamma 拖动或预设切换自动重试。点击重新检测或恢复时才允许重试。
- Profile 新增 `hardwareEnabled`。新默认预设为 false；旧配置未带此字段时按 true 读取，以保留既有硬件预设语义。关闭后保留所有参数但不发送硬件命令；开关变化需保存预设。
- 没有包含在 Profile 中的硬件参数保持当前值，不再隐式恢复。关闭整个效果、原始对比或退出仍会尝试恢复可用硬件项，失败项保留。
- 用户启用效果时如有旧 Gamma 记录，先独立恢复 Gamma 原值再建立新会话；这一步不调用 DDC。Gamma 自身恢复失败仍不能假称 Gamma 可用。
- 正常退出可留下未恢复的硬件项，其原值在下次启动提示；仅 Gamma 恢复失败仍阻止普通退出并显示错误。

## 数据与兼容

- `recovery.json` 保留 Gamma 原值；`hardware-recovery.json` 按显示器稳定 ID 保存各硬件项原值。
- 首次运行新版本会自动拆分旧的混合恢复记录：先原子持久化硬件原值，再从 Gamma 记录移除硬件部分。中断后可重复迁移，不丢唯一原值。
- 新 Gamma 会话或另一台显示器的硬件操作不会覆盖旧硬件记录；每项只有确认恢复且进度持久化成功后才从硬件记录删除。
- 待恢复记录不是配置，不因导入或切换 Profile 丢弃。

## 验证

Rust 故障注入测试覆盖单项失败后的隔离、健康项继续工作、仅 Gamma 切换零硬件读写、写前日志失败、恢复日志失败、多显示器记录隔离、旧 Profile 兼容和迁移中断重放。模拟恢复测试不写真实显示器。

浏览器演示验证：关闭 Profile 硬件开关后硬件输入禁用；Gamma 输入保持可用，调整至 1.25 并启用效果成功。随后恢复演示状态，未保存测试改动。

本轮不启动真实 GUI，不改变用户实际显示器参数或应用数据；实际故障场景仍需用户用新版本验收。

结果：28 项 Rust 测试通过，TypeScript/Vite 与 Tauri release 构建通过，`git diff --check` 通过。交付文件为 `.local/artifacts/LumaShift-0.1.2.exe`。
